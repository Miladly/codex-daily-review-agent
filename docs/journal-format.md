# 每日工作记录与复盘

日报首先是一份以后能找回工作事实的日志，随后才是对这些工作的复盘。统一阅读顺序：

1. **今日工作概览**：按原项目归并，当天记录的简要入口。
2. **分项目工作记录**：做过什么、处理结果或阶段状态、时间线和相关产物。
3. **复盘思考**：少量决定、问题或经验，事实与判断分开。
4. **后续事项与完成标准**：最多三条日级建议；不能把后续已报告修复的工作重复写成未处理。
5. **人工补充及来源**：保留个人补漏、判断与感受，证据支持回查。

## 默认本地运行

`daily --through today --days 3` 不调用模型。它从去重事件中按全天选取工作记录，保留当天末尾的进展陈述，按时间排列。正文有展示上限，详细已选记录与会话层结构保存在私有JSON；完整已采集事件仍在SQLite中。缺失或截断不代表没有工作。

规则后端提供的是工作摘录和复盘线索，不能自动解释科学因果、判定相似事项已关闭，或写出个人感受。命令退出成功、部署、测试通过及助手自述均保留原证据边界。后续建议会明确提醒先核对是否已有后续处理。

## 可选模型提炼

用户授权后，可先检查 `model-preview`，再使用 `review --backend codex`。方法版本1.1.0明确要求项目/会话层以 `work_records` 为主体，记录动作、产出与阶段，不只输出解释和待办；日级复盘和下一步各保持少量内容。

程序把模型工作记录放到正文的记录区，并保留原规则记录作为私有归档；复盘判断另列。模型没有返回某个项目的工作记录时，正文回退到该项目的规则记录，避免用空白或纯反思覆盖工作历史。来源引用、等级、当日/历史边界和工具活动仍受校验。语义准确性需要人工审阅。

这是可选外发步骤。更改格式、更新skill或设置定时任务，不等于授权每天发送私人工作内容给模型。

## 周报、月报可复用的字段

同日私有JSON包含：

- `format = record-review-1`，以及版本化的 `review_method`。
- 日报、项目、会话层的 `work_records`：稳定记录ID、日期、原项目ID与名称、会话ID、时间、工作摘要、记录的结果/状态、证据等级、引用及产物。
- 可选 `model_work_records`：按日期和原项目ID索引的模型提炼；原规则记录保留。
- `daily`、可选 `model_summary`、历史线索及候选建议，供进一步区分事实、判断和计划。

规则状态 `observed` 表示日志可观察操作，`reported` 表示会话中的陈述；它们不是“独立验收完成”枚举。`result` 保留摘录中的结果文字，不由规则推断科学结论。产物链接仅来源于已有记录，不自动读取或验证文件，也不打开远程目标。

未来汇总时以原项目ID连接多日记录，合并同一产物或实验的阶段变化，再提炼成果和问题。不要把多次进度播报算成多次独立实验，不要将每日反思直接拼接当作事实年表。本版未新增自动周报/月报生成命令。

真实笔记、结构化记录和证据都属于私有数据。仓库只包含程序、说明和合成示例。
